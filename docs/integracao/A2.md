```csharp
modelBuilder.Entity<Categoria>(categoria =>
{
    // varchar(60). NOT NULL vem do tipo não anulável (string, com Nullable habilitado).
    categoria.Property(c => c.Nome)
        .HasMaxLength(Categoria.NomeTamanhoMaximo);
```

Dentro do bloco **existente** `modelBuilder.Entity<Produto>(produto => { ... })`, ao final:

```csharp

    // tem produtos, ativos ou inativos (R9). O EF cria o índice IX_Produtos_CategoriaId
    // e nomeia a FK FK_Produtos_Categorias_CategoriaId por convenção.
```

## Migration — nome, comando, SQL manual e onde inserir

**Nome:** `CriarCategorias` (M2). Gerada pelo dono com
`dotnet ef migrations add CriarCategorias --project MyCRUD` ou escrita à mão (Q4).
Antes de aplicar no Supabase: `SELECT "CategoriaId", count(*) FROM "Produtos" GROUP BY 1 ORDER BY 1;`

`Up()` completo — passos 2–4 (SQL manual) **logo após o `CreateTable`**:

```csharp
/// <summary>
/// Cria a tabela de categorias, adota os CategoriaId já usados por produtos
/// e liga Produtos → Categorias com chave estrangeira RESTRICT.
/// </summary>
protected override void Up(MigrationBuilder migrationBuilder)
{
    // 1. Tabela nova.
    migrationBuilder.CreateTable(
        name: "Categorias",
        columns: table => new
        {
            Id = table.Column<int>(type: "integer", nullable: false)
                .Annotation("Npgsql:ValueGenerationStrategy", NpgsqlValueGenerationStrategy.IdentityByDefaultColumn),
            Nome = table.Column<string>(type: "character varying(60)", maxLength: 60, nullable: false)
        },
        constraints: table =>
        {
            table.PrimaryKey("PK_Categorias", x => x.Id);
        });

    // 2. R11: cada CategoriaId já usado vira "Categoria N" com o MESMO Id,
    //    senão a FK do passo 6 falharia para os produtos existentes.
    //    Identity "BY DEFAULT" aceita Id explícito no INSERT.
    migrationBuilder.Sql("""
        INSERT INTO "Categorias" ("Id", "Nome")
        SELECT DISTINCT "CategoriaId", 'Categoria ' || "CategoriaId"
        FROM "Produtos";
        """);

    // 3. Os INSERTs acima não avançam a sequência do identity: sem isto, o próximo
    //    cadastro tentaria Id 1 e colidiria. GREATEST(..., 0): a sequência começa em 1
    //    (MINVALUE 1); se só houver Ids 0/negativos, setval negativo daria erro.
    migrationBuilder.Sql("""
        SELECT setval(
            pg_get_serial_sequence('"Categorias"', 'Id'),
            GREATEST(COALESCE((SELECT MAX("Id") FROM "Categorias"), 0), 0) + 1,
            false);
        """);

    // 4. R8/D6: nome único sem diferenciar maiúsculas ("Bolos" = "bolos").
    migrationBuilder.Sql("""
        CREATE UNIQUE INDEX "IX_Categorias_Nome_Minusculo" ON "Categorias" (lower("Nome"));
        """);

    // 5. Índice da FK (gerado pelo EF).
    migrationBuilder.CreateIndex(
        name: "IX_Produtos_CategoriaId",
        table: "Produtos",
        column: "CategoriaId");

    // 6. FK RESTRICT (gerada pelo EF).
    migrationBuilder.AddForeignKey(
        name: "FK_Produtos_Categorias_CategoriaId",
        table: "Produtos",
        column: "CategoriaId",
        principalTable: "Categorias",
        principalColumn: "Id",
        onDelete: ReferentialAction.Restrict);
}

protected override void Down(MigrationBuilder migrationBuilder)
{
    migrationBuilder.DropForeignKey(
        name: "FK_Produtos_Categorias_CategoriaId",
        table: "Produtos");

    migrationBuilder.DropIndex(
        name: "IX_Produtos_CategoriaId",
        table: "Produtos");

    // IX_Categorias_Nome_Minusculo cai junto com a tabela.
    migrationBuilder.DropTable(
        name: "Categorias");
}
```

`using` da migration: `Microsoft.EntityFrameworkCore.Migrations` e `Npgsql.EntityFrameworkCore.PostgreSQL.Metadata`.

## Pendências / dúvidas

1. **Desvio do contrato 2.7 (passo 3 da M2):** usei `GREATEST(COALESCE(MAX,0),0) + 1` no `setval`.
   O texto do contrato (`COALESCE(MAX,0) + 1`) falha se só houver `CategoriaId` negativos
   (sequência identity tem `MINVALUE 1`). Integrador: aceitar ou ajustar o contrato.
2. **R7 no tratador** cobre `PostgresException` direto, além de `DbUpdateException`:
   `ExecuteDeleteAsync`/`ExecuteUpdateAsync` não embrulham o erro do banco. Afeta A4 (R29) e A5 também — positivo.
3. Mensagem do R7 é genérica ("Registro em uso."); um `POST /produtos` com categoria apagada no meio também cai nela. Conforme contrato.
4. Escape de `%`, `_`, `\` para ILIKE (R5) está privado em `CategoriaEndpoints.EscaparCuringasLike`.
   A3/A4/A5 provavelmente repetem: candidato a helper em `Compartilhado/` (arquivo do integrador) na revisão.
5. Não compilado (sem .NET no ambiente). Pontos para o CI confirmar: `[AsParameters]` com record +
   valores padrão no construtor; subconsulta `db.Produtos.Count(...)` dentro do `Select`.
6. Tela testada com Playwright e API simulada (Admin e Operador): cadastrar, 409, editar, excluir, filtro, sem erros de JS.
