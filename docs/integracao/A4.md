## AppDbContext.cs

```csharp
using MyCRUD.Pedidos;   // junto dos outros using
```

DbSets (junto dos existentes):

```csharp
public DbSet<Pedido> Pedidos => Set<Pedido>();
public DbSet<ItemPedido> ItensPedido => Set<ItemPedido>();
```

Dentro de `OnModelCreating`, depois do bloco de `Cliente` (A3):

```csharp
modelBuilder.Entity<Pedido>(pedido =>
{
    // Enum gravado como texto ("Aberto"), não como número: legível no banco (D10).
    pedido.Property(p => p.Status)
        .HasConversion<string>()
        .HasMaxLength(Pedido.StatusTamanhoMaximo);

    // Cliente com pedido não pode ser excluído (D12): RESTRICT em vez de CASCADE.
    pedido.HasOne(p => p.Cliente)
        .WithMany()
        .HasForeignKey(p => p.ClienteId)
        .OnDelete(DeleteBehavior.Restrict);

    // Itens pertencem ao pedido. Pedido nunca é excluído (R31), mas o CASCADE
    // documenta que item não existe sem pedido.
    pedido.HasMany(p => p.Itens)
        .WithOne()
        .HasForeignKey(i => i.PedidoId)
        .OnDelete(DeleteBehavior.Cascade);

    // Listagem ordena e filtra por data de entrega.
    pedido.HasIndex(p => p.DataEntrega);   // IX_Pedidos_DataEntrega

    // O banco recusa qualquer status fora do enum, mesmo vindo de SQL manual.
    pedido.ToTable(t => t.HasCheckConstraint(
        "CK_Pedidos_Status",
        "\"Status\" IN ('Aberto','Confirmado','Entregue','Cancelado')"));
});

modelBuilder.Entity<ItemPedido>(item =>
{
    // numeric(10,2), igual a Produto.Preco: o preço congelado cabe sem arredondar.
    item.Property(i => i.PrecoUnitario)
        .HasPrecision(10, 2);

    // Produto usado em pedido não pode ser apagado (e nem é: R14 só desativa).
    item.HasOne(i => i.Produto)
        .WithMany()
        .HasForeignKey(i => i.ProdutoId)
        .OnDelete(DeleteBehavior.Restrict);   // gera também IX_ItensPedido_ProdutoId

    // Um produto no máximo uma vez por pedido. Este índice também cobre a FK PedidoId,
    // por isso o EF não cria um IX_ItensPedido_PedidoId separado.
    item.HasIndex(i => new { i.PedidoId, i.ProdutoId })
        .IsUnique();                          // IX_ItensPedido_PedidoId_ProdutoId

    item.ToTable("ItensPedido", t =>
    {
        t.HasCheckConstraint(
            "CK_ItensPedido_Quantidade",
            $"\"Quantidade\" BETWEEN 1 AND {ItemPedido.QuantidadeMaxima}");
        t.HasCheckConstraint(
            "CK_ItensPedido_PrecoUnitario",
            "\"PrecoUnitario\" > 0");
    });
});
```

Tipos que o Npgsql deduz sozinho: `DateOnly` → `date`; `DateTime` → `timestamp with time zone`; `int` PK → identity.

## Migration

M4 `CriarPedidos` (depois de M3 `CriarClientes`):

```bash
dotnet ef migrations add CriarPedidos --project MyCRUD
```

Sem SQL manual: os CHECKs vêm de `HasCheckConstraint`. Ordem esperada no `Up()`:

1. `CreateTable "Pedidos"` (Id identity, ClienteId, DataEntrega `date`, Status `varchar(20)`, CriadoEm `timestamptz`) + `CK_Pedidos_Status` + `FK_Pedidos_Clientes_ClienteId` RESTRICT
2. `CreateTable "ItensPedido"` (Id identity, PedidoId, ProdutoId, Quantidade, PrecoUnitario `numeric(10,2)`) + `CK_ItensPedido_Quantidade` + `CK_ItensPedido_PrecoUnitario` + `FK_ItensPedido_Pedidos_PedidoId` CASCADE + `FK_ItensPedido_Produtos_ProdutoId` RESTRICT
3. Índices: `IX_Pedidos_ClienteId`, `IX_Pedidos_DataEntrega`, `IX_ItensPedido_PedidoId_ProdutoId` (unique), `IX_ItensPedido_ProdutoId`

`Down()`: `DropTable "ItensPedido"` → `DropTable "Pedidos"`. Tabelas novas e vazias: sem impacto em dados.

## Pendências / dúvidas

- **Sem compilação local.** Pontos a observar no 1º CI: `ExecuteUpdateAsync(setters => setters.SetProperty(...))` (API do EF Core 10) e `EF.Functions.ILike(..., "\\")` (overload com escape, Npgsql).
- **Fuso horário**: `TimeZoneInfo.FindSystemTimeZoneById("America/Sao_Paulo")` precisa de tzdata/ICU no SO. Ok em Windows, Debian/Ubuntu e na imagem `mcr.microsoft.com/dotnet/aspnet` padrão; em imagem Alpine/chiseled sem `tzdata`, a 1ª criação de pedido daria 500.
- **Protótipo diverge do contrato**: `prototipos/pedido-detalhe.html` marca "Cancelar" de pedido **Aberto** como `so-admin`. A tela real segue o contrato (R30: qualquer logado cancela Aberto). Protótipo sai na Fase 4 (Q5).
- `EscaparLike` é privado em `PedidoEndpoints`; se A2/A3/A5 tiverem o mesmo helper, o integrador pode mover para `Compartilhado` depois.
- 403 do cancelamento devolve `title` "Apenas Admin pode cancelar um pedido Confirmado."; se o A5 fizer `mensagemDeErro` trocar todo 403 pela frase genérica, a tela mostra a genérica (aceitável).
- `pedidos.html` consome `GET /clientes/?tamanho=100` (A3) e `GET /produtos/?situacao=Ativos&tamanho=100` (A5) no formato `ResultadoPaginado`; usa `cliente.id/nome` e `produto.id/nome/preco`.
- Ordem do `Validator`: `CriarPedidoDto.Validate` (itens) só roda se os atributos passarem; data/cliente/produtos (endpoint) só depois disso. Aceito; documentado no DTO.
