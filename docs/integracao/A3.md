Bloco em `OnModelCreating`:

```csharp
modelBuilder.Entity<Cliente>(cliente =>
{
    cliente.Property(c => c.Nome)
        .HasMaxLength(Cliente.NomeTamanhoMaximo);

    // Só dígitos (10 ou 11). A API já normaliza; o CHECK impede que um INSERT
    // feito por fora da API (SQL manual, seed) grave telefone com máscara.
    cliente.Property(c => c.Telefone)
        .HasMaxLength(Cliente.TelefoneTamanhoMaximo);

    cliente.Property(c => c.Email)
        .HasMaxLength(Cliente.EmailTamanhoMaximo);

    // Índice para a listagem, que ordena por Nome (R19). Telefone NÃO é único (Q3).
    cliente.HasIndex(c => c.Nome)
        .HasDatabaseName("IX_Clientes_Nome");

    cliente.ToTable(tabela => tabela.HasCheckConstraint(
        "CK_Clientes_Telefone", "\"Telefone\" ~ '^[0-9]{10,11}$'"));
});
```

Nulabilidade vem do C# (`<Nullable>enable</Nullable>`): `Nome` e `Telefone` NOT NULL, `Email` NULL.

    {
        b.Property<int>("Id")

            .IsRequired()

            .HasColumnType("character varying(120)");

        b.Property<string>("Telefone")
            .IsRequired()
            .HasMaxLength(11)
            .HasColumnType("character varying(11)");

## Verificação manual

Scalar (`/scalar`) ou a tela `/clientes.html`, logado como Operador e depois como Admin:

1. **R1** — sem cookie, `GET /clientes` → 401.
2. **R18** — `POST /clientes` `{ "nome": "  Maria  ", "telefone": "(19) 99999-0000", "email": " Maria@Ex.com " }` → 201, resposta `nome: "Maria"`, `telefone: "19999990000"`, `email: "maria@ex.com"`.
3. **R18** — telefone `"1234"` ou `"(19) 9999-99999-9"` → 400 `errors.Telefone`; `email: ""` → 400 `errors.Email`; `email: null` → 201.
4. **Q3** — cadastrar outro cliente com o mesmo telefone → 201 (não é único).
5. **R19** — `?busca=mar` acha "Maria"; `?busca=(19) 9999` acha pelo telefone; `?busca=50%` não vira curinga; ordem por Nome, empates por Id.
6. **R4** — `?pagina=0` ou `?tamanho=101` → 400; `?pagina=99` → 200 com `itens: []` e `total` real.
7. **R20** — Operador: botão Excluir não aparece; `DELETE /clientes/1` via Scalar → 403. Admin: cliente sem pedidos → 204; cliente com pedido (depois do A4) → 409 "Cliente possui pedidos."
8. `PUT /clientes/999` → 404; tela mostra "Este cliente não existe mais…".
9. Banco: `INSERT INTO "Clientes" ("Nome","Telefone") VALUES ('x','(19) 9999-0000');` → erro `CK_Clientes_Telefone`.

## Pendências / dúvidas

- **Ordem de integração (3.6):** `ClienteEndpoints.Excluir` usa `db.Pedidos.AnyAsync(p => p.ClienteId == id)`, como mandado pelo dono. Na ordem A3 → A4, o projeto **não compila** entre os dois passos. Opções: (a) integrar A3 e A4 no mesmo passo (M3 e M4 continuam separadas); (b) integrar A4 antes do A3 não serve (A4 depende de `Cliente`). Sugestão: **(a)**.
- **R7:** a corrida "pedido criado entre a verificação e o DELETE" vira 409 só se o `TratadorGlobalDeExcecoes` (A2) reconhecer `DbUpdateException` com `PostgresErrorCodes.ForeignKeyViolation`. Por isso o DELETE usa `Remove` + `SaveChangesAsync` (e não `ExecuteDeleteAsync`, cuja exceção não vem embrulhada em `DbUpdateException`).
- `FiltroClientes.Busca` tem `MaxLength(120)` (não listado no contrato, só restringe; evita padrão `ILIKE` gigante).
- Constante extra `Cliente.TelefoneTamanhoMinimo = 10` (usada pelo atributo `[TelefoneBrasileiro]`).
